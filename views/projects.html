Risk Assessment

ENTERPRISE

Semantic intelligence over ABAP code quality — built at SAP Labs

ABAP ATC (ABAP Test Cockpit) surfaces code quality findings across an SAP codebase. But a finding code and its message, on their own, do not explain why it matters in your specific context, what patterns caused it, or how to approach fixing it. Looking up a finding by code is a database query. Understanding what it means in the context of your code requires reasoning over related information — that is a different problem entirely.

This project built a RAG-based semantic search solution over ATC content using SAP HANA Cloud as the vector store. Developers describe what they are seeing or ask a question in plain language. The system retrieves semantically relevant findings, explanations, and related patterns, then provides contextual answers through an LLM. Document processing, embedding, and semantic indexing are handled through FastAPI services built in Python.

The capability is integrated back into ABAP via OAuth 2.0, making it callable directly from within SAP systems. Built as part of an enterprise AI initiative at SAP Labs — production context, real codebase, real findings data.

DeepTicker

IN PROGRESS

Predicting Indian stock prices to automate personal trading — and eventually, much more

The goal behind DeepTicker is specific. If the model can predict next-day closing prices with enough accuracy, the plan is to automate trading decisions around it — personal stop-loss strategies first. Then, eventually, a registered company running automated strategies: earn passively, invest in small businesses as a silent partner, take a share of the profit with no management overhead. The platform needs to work well enough to be trusted with real capital. That is the north star.

Rather than training one model across all NSE stocks, DeepTicker trains eleven separate Transformer neural networks — one per market sector — so each model learns the price behaviour specific to that domain. The prediction pipeline is built as composable sklearn-compatible transformers: 60-day lookback sequence construction, feature scaling, and inverse transformation to recover real prices from normalised predictions. The architecture is designed for experimentation — add a new feature in one place and the pipeline adapts everywhere, without changes scattered across the codebase.

The backend uses a configuration-driven database layer: swap MySQL for any other database by updating a config file, and every API endpoint works automatically. New tables get read/write/update support out of the box. The API is also exposed as an MCP server, making predictions directly callable from AI agents.

End-to-end prediction works today — select any NSE stock, the system fetches its sector, loads the corresponding model, and returns a predicted next-day close price alongside an ATR-based stop-loss level. The frontend is a vanilla JavaScript SPA for stock data management and prediction display. The 80%+ accuracy target — the threshold needed to trust it with real money — is the active work.

CodeAtlas

EXPERIMENT

AI assistant that analyses code and builds architecture diagrams through conversation

Large codebases — especially in enterprise environments like SAP ABAP — evolve over decades. Architecture diagrams either were never created, or fell out of sync as delivery pressure took priority. Understanding any existing functionality means weeks of manual code tracing with no map to guide you.

CodeAtlas lets a developer paste code or describe a feature in plain language. The agent analyses it — identifying actors, processes, data flows, and integrations — and drafts a Mermaid diagram in the chat. The user refines it iteratively through conversation. When it looks right, the user confirms, and the actual diagram image is rendered. The agent never renders without that confirmation.

The backend is a FastAPI server running a LangGraph StateGraph, with SQLite checkpointing for persistent multi-session memory. The Streamlit frontend connects over HTTP with SSE streaming. Full thread management is implemented — create, rename, and delete conversations. The LLM provider is configurable via a single environment file. The next step is fetching ABAP code directly from a connected SAP system via ADT API, so developers don't have to paste anything manually.

Customer360

PROTOTYPE

A cross-channel recommendation platform — no cold start, no data silos

Every business building a recommendation system faces the same problem at the start: no data. The model has nothing to learn from, so early recommendations are useless. And even after launch, the model only ever sees a slice of a customer's life — what they bought from that one business, nothing else.

Customer360 is built on a different idea. A central model trained on data from multiple businesses across different domains. A person booking a badminton court tells you something about what they might want to buy. One business generates the signal; another business benefits from it. Any new company subscribing gets useful predictions from day one — the cold start problem disappears because the central model already knows the customer from other channels.

What exists today is a prototype of the recommendation engine — the foundation the full vision sits on. It segments customers into sixteen behavioural clusters using KMeans, then runs a cluster-specific SVD collaborative filtering model to return ranked product recommendations. Two modes are supported: personalized (phone number lookup) and generic (demographic input for anonymous visitors). The research layer explored Neural Collaborative Filtering, TF-IDF, BERT embeddings, and DPMM clustering across seven Jupyter notebooks before settling on the best-performing approach. The cross-channel data layer is the next step.
