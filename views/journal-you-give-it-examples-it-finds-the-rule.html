You Give It Examples. It Finds the Rule.

How AI programming is different from conventional programming.

Every programmer learns the same way. You are given a problem, you think about the logic, you write the rules, and you run the program.

It is clean. It is predictable. If something goes wrong, you read the code, find where the logic breaks, and fix it. The machine does exactly what you tell it. Nothing more. Nothing less.

Let me take a simple example. The AND gate.

The AND Gate — The Conventional Way

An AND gate takes two inputs — A and B — and returns 1 only when both are 1. In every other case, it returns 0.

TRUTH TABLE — AND GATE

A B Output
000
010
100
111

In conventional programming, you look at this table and write the rule immediately.

CONVENTIONAL CODE

def and_gate(A, B):
    if A == 1 and B == 1:
        return 1
    return 0

Done. Three lines. You read the problem, you wrote the rule, the program works. That is how conventional software is built.

But now let me ask a different question.

What if you did not write the rule — but instead showed the program every possible example, and let it figure the rule out on its own?

The AI Way — The Perceptron

In 1957, Frank Rosenblatt introduced the perceptron — the simplest building block of artificial intelligence. It was inspired by how a single neuron in the brain works.

A perceptron takes inputs, assigns a weight to each one, adds them up, adds a bias, and passes the result through an activation function. If the result crosses a threshold, it fires 1. Otherwise, 0.

HOW A PERCEPTRON WORKS

INPUTS

A, B

→

WEIGHTED SUM

(A × w1) + (B × w2) + bias

→

OUTPUT

0 or 1

Now — and this is the key part — the perceptron does not start with the right weights. It starts with random ones. It could start with anything.

Then, training begins. You show it the first example: A=0, B=0, expected output=0. The perceptron calculates its answer. If it is wrong, it adjusts its weights slightly in the direction of the correct answer. You repeat this for all four examples, over and over, until the perceptron stops making mistakes.

What Training Actually Looks Like

Imagine the perceptron starts with completely random weights — say w1=0.5, w2=0.3, bias=-0.4. It has no idea what an AND gate is. It has never been told the rule.

In the first pass, it will get some answers wrong. It looks at A=1, B=1 and might output 0 when the correct answer is 1. It adjusts. It looks at A=0, B=1 and might output 1 when the correct answer is 0. It adjusts again.

After enough iterations — typically just a few hundred — something remarkable happens. The weights settle. The perceptron has found values for w1, w2, and bias that correctly produce the right output for every single input combination.

It discovered the rule. Without being told what it was.

Here is what makes this different.

It does not matter what weights you start with. Given enough examples and enough iterations, the perceptron will always converge to the correct answer.

Two Completely Different Ways of Thinking

In my previous journal entry, I described a mental model that I find very useful when thinking about AI.

CONVENTIONAL SOFTWARE

Input + Rules → Output

⇄

AI / MACHINE LEARNING

Input + Output → Rules

The AND gate makes this concrete. In the conventional approach, you wrote the rule and the program executed it. In the perceptron approach, you gave it the inputs and the outputs — all four rows of the truth table — and it found the rule on its own.

For the AND gate, both approaches work perfectly. The conventional solution is actually simpler. So why does this matter?

It matters because the AND gate is a toy example. A teaching example. The rule for an AND gate is trivially obvious — any programmer can write it in three lines.

But what about problems where the rule is not obvious? What about problems where the rule involves thousands of variables? What about problems where the rule exists — in the data — but no human has ever been able to write it down?

That is where the perceptron's approach becomes powerful. Not for AND gates. For the problems where the rule was never knowable in the first place.

The perceptron is the simplest proof that a machine can learn without being told what to learn.

But a single perceptron has limits. And those limits, when they were discovered, nearly ended AI research entirely. That is the story I want to tell next.
